# 手臂通訊方式（進階）

這份說明給想了解「電腦怎麼叫手臂動」的同學。一般使用不需要看。

## 韌體：`firmware/arm_controller/arm_controller.ino`

改自社團 movearm 專案的 `arm_controller.ino`，**通訊格式完全相同**，所以 movearm.py 也能繼續用。

| 項目 | 內容 |
|---|---|
| 鮑率 | 115200 |
| 開機訊息 | `System Ready`（程式連線時會等這一行，確認韌體正確） |
| 指令格式 | 一行四個角度：`底座,大臂,前臂,腕\n`，例如 `0.0,-19.0,-15.0,90.0` |
| 角度正負 | 和 movearm 一樣：**大臂、前臂送出時取負號**（介面上的 +19° 送出 `-19.0`） |
| 完成回覆 | 馬達從「移動中」變成「停止」時回一次 `OK` |
| 腳位 | 步進 STEP 2/3/4、DIR 5/6/7、ENABLE 8；pin 9 是伺服（本專案固定送 90，不會動它） |
| 換算 | 200 步 × 16 微步 / 360° ≈ 8.89 步／度 |

和原版的差別：原版收到目標就以固定約 94°/s 從靜止直接衝出去、到點急停，有負載的軸容易**失步**（只在原地抖）。
這一版每一軸都用「慢慢加速 → 等速 → 慢慢減速」的方式移動，參數在檔案最上面：

```cpp
const float MAX_SPEED_DEG_S = 60.0;   // 最高速度
const float ACCEL_DEG_S2    = 120.0;  // 加速度
```

改了這兩個數字，也請同步修改 `config/digit_arm.yaml` 的 `firmware_max_speed_deg_s`、`firmware_accel_deg_s2`（程式用來估計時間和判斷逾時）。

注意：這個韌體**沒有**「查詢位置」和「緊急停止」指令，也沒有編碼器。它只知道自己送出了幾步，不知道手臂實際在哪裡。
所以每次連線前都要用手把手臂擺到同一個 HOME 姿勢。

## 程式怎麼送指令

- 只會送出兩種姿勢，以及它們之間連線上的點：**起點（HOME）** 和 **動作點（HOME + 設定的角度）**，連線前就會先檢查範圍。
- 預設動作點：大臂 +19°、前臂 +15°（來自社團繪圖校正資料 `movearm_wall.json` 的一個校正點）。
- 每半程都要等到 `OK` 才繼續；逾時、USB 斷線、收到 `System Ready`（代表 Arduino 重開）都會立刻停止，並要求重新擺回 HOME 再連線。
- 如果連線時收到 `READY`，代表板子上是別的繪圖韌體，程式會拒絕連線，也不會送任何動作。

## 其他韌體裡的指令（這個專案沒有使用）

社團的繪圖程式（ArmDraw）用過 `H`、`G0`、`G1`、`M3`、`M5`、`M2` 等指令，它們屬於另一份繪圖韌體：

| 指令 | 在繪圖韌體裡的意思 |
|---|---|
| `H` | 把目前姿勢登記為原點（不會移動） |
| `G0` / `G1` | 移動到 A/B/C 角度（兩者速度相同） |
| `M3` / `M5` | 落筆／抬筆 |
| `M2` | 關閉馬達電源 |

movearm 的 `arm_controller.ino`（包含本專案的加減速版）**不認得**這些指令，本專案也不會送出。

## 在 Windows 與 WSL 之間

WSL 看不到筆電鏡頭，COM 埠也預設留在 Windows，所以：

- `workers/camera_worker.py`：在 Windows 上開鏡頭、跑 MediaPipe，把畫面和手部關鍵點傳給 WSL 裡的 ROS 節點。
- `workers/serial_bridge.py`：在 Windows 上開 COM 埠，逐行轉送；它不理解也不產生任何手臂指令，所有控制邏輯都在 ROS 的動作節點。

也可以用 usbipd 把 Arduino 轉進 WSL，改用 `port:=/dev/ttyUSB0`。
